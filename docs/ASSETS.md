# ТЗ на ассеты «КРАСНЫЙ ФЛАГ»

Документ описывает все графические и звуковые файлы, которые игра умеет
подхватывать. Правила общие для всех пунктов:

- **Ничего не обязательно.** Каждый ассет имеет встроенную замену: нет файла —
  работает вариант, нарисованный кодом. Игра не ломается никогда.
- **Путь = подключение.** Достаточно положить файл по указанному пути в
  `public/`. Ни строчки кода править не нужно: пути собраны в
  `src/core/assets.ts`, подключение — в `src/main.ts`.
- **Проверка типа.** Игра проверяет не только наличие файла, но и его тип
  (`image/*`, `audio/*`). Файл с неверным расширением будет проигнорирован, а не
  показан битой картинкой.
- **Вес.** Суммарный бюджет страницы — до 3 МБ. Сейчас занято ≈1,1 МБ.
- **Формат.** Для фотографий — `.webp` (в 2–3 раза легче `.jpg` при том же
  качестве). Для графики с прозрачностью — `.png`. Для иконок и логотипа — `.svg`.

Приоритет: **P1** — заметно поднимет качество, **P2** — желательно,
**P3** — по возможности.

## 2. Звук

### 2.1. Фоновая музыка — P1

- **Путь:** `public/media/music/theme.mp3`
- **Формат:** mp3, 128–160 kbps, моно или стерео, до 2 МБ
- **Длительность:** 60–120 секунд, **бесшовная петля**
- **Характер:** спокойный тревожный эмбиент, минор, темп 70–85 BPM.
  Без ударных с резкой атакой, без вокала, без резких всплесков громкости —
  музыка играет под чтение текста и не должна перетягивать внимание.
- **Громкость:** нормализовать по −18 LUFS. Игра дополнительно приглушает
  музыку на экранах разбора.
- **Критично:** первая и последняя секунда должны стыковаться без щелчка.
  Проверяется просто: зациклить в любом плеере и послушать 3 круга.
- **Заменяет:** синтезированную тему из четырёх аккордов.

### 2.2. Звуковые эффекты — P2

- **Путь:** `public/media/sfx/<имя>.mp3`
- **Формат:** mp3 128 kbps или ogg, до 40 КБ каждый, тишина в начале файла
  не более 10 мс (иначе отклик будет запаздывать)

| Имя файла | Когда звучит | Характер, длительность |
|---|---|---|
| `hit.mp3` | отмечен настоящий признак риска | короткий чистый подтверждающий тон, 0,15 с |
| `miss.mp3` | клик по нормальному фрагменту | глухой низкий отказ, 0,2 с |
| `click.mp3` | нажатие кнопки меню | сухой щелчок, 0,07 с |
| `paper.mp3` | появление документа | шелест бумаги, 0,3 с |
| `stamp.mp3` | принято решение | удар штампа по бумаге, 0,25 с |
| `good.mp3` | решение верное | короткий мажорный аккорд, 0,4 с |
| `bad.mp3` | решение ошибочное | нисходящий минорный аккорд, 0,4 с |
| `timeout.mp3` | время документа истекло | сирена-затухание, 0,5 с |
| `tick.mp3` | последние 5 секунд | тик метронома, 0,05 с |
| `final.mp3` | итоговый экран | аккорд-разрешение, 1 с |

> Поддержку файлов эффектов нужно будет включить в коде (сейчас они
> синтезируются). Скажите, когда файлы будут готовы, — добавлю загрузчик,
> он занимает ~30 строк.

## 3. Интерфейс

### 3.1. Логотип — P1

- **Путь:** `public/media/ui/logo.svg`
- **Формат:** SVG, без внешних шрифтов (текст переведён в кривые), до 60 КБ
- **Размер холста:** ширина 600–900, пропорции свободные, высота не больше ширины
- **Содержание:** знак + надпись «КРАСНЫЙ ФЛАГ». Показывается на тёмном фоне
  поверх фотографии, поэтому светлые элементы обязательны; чисто тёмный логотип
  пропадёт.
- **Поля:** 4–6% пустого пространства внутри viewBox со всех сторон.
- **Заменяет:** нарисованный кодом флаг на стартовом экране.

### 3.2. Печати для экрана разбора — P1

- **Путь:** `public/media/ui/stamp-stop.png`, `stamp-pass.png`, `stamp-warn.png`,
  `stamp-fail.png`
- **Формат:** PNG с альфа-каналом, 640×300, до 120 КБ каждый
- **Подключаются все четыре сразу:** если не хватает хотя бы одной, игра
  использует нарисованные рамки для всех — иначе экраны выглядели бы разнородно.

| Файл | Надпись | Цвет | Когда |
|---|---|---|---|
| `stamp-stop.png` | ОСТАНОВЛЕНО | красный | документ с нарушением остановлен верно |
| `stamp-pass.png` | ПРОВЕРЕНО | зелёный | чистый документ пропущен верно |
| `stamp-fail.png` | ОШИБКА | тёмно-красный | решение неверное |
| `stamp-warn.png` | ВРЕМЯ ВЫШЛО | янтарный | время документа истекло |

- **Стиль:** оттиск резинового штампа — неровные края, пропуски краски,
  лёгкий поворот уже добавляется кодом (не наклоняйте сами).
- **Важно:** надпись не должна упираться в края, прозрачность вокруг рамки
  обязательна, тени не рисовать.

### 3.3. Рамка панелей (9-slice) — P2

- **Путь:** `public/media/ui/panel-frame.png`
- **Формат:** PNG с альфой, 256×256, до 60 КБ
- **Как устроено:** это «растягиваемая рамка». Углы 28×28 пикселей остаются
  неизменными, стороны растягиваются, центр заливается. Поэтому:
  - углы должны умещаться в 28 пикселей;
  - стороны — одинаковыми по всей длине (никаких орнаментов, которые нельзя
    растянуть);
  - центр — однотонный или полупрозрачный.
- **Применяется к:** карточке разбора раунда, итоговому экрану, окнам
  «О проекте» и «Настройки».
- **Если размер углов другой** — скажите, поменяю число в одной CSS-переменной.

### 3.4. Рамка кнопок (9-slice) — P2

- **Путь:** `public/media/ui/button-frame.png`
- **Формат:** PNG с альфой, 192×96, углы 26 пикселей, до 40 КБ
- **Применяется к:** кнопкам «НАЧАТЬ ПРОВЕРКУ», «ПРОПУСТИТЬ», «ОСТАНОВИТЬ».
- **Нюанс:** цвет надписи задаёт игра, рисовать текст на ассете нельзя.
  Кнопки бывают трёх смыслов (основная, «пропустить», «остановить») — нужен
  нейтральный вариант, цветом их разводит код.

### 3.5. Иконки — P3

- **Путь:** `public/media/ui/icons.svg` (спрайт `<symbol id="...">`)
- **Нужны:** `time`, `score`, `doc`, `accuracy`, `settings`, `sound-on`,
  `sound-off`, `flag`, `check`, `clock`
- **Формат:** штриховые, толщина 1,7–2 пикселя на сетке 24×24, `stroke`
  наследует цвет (`currentColor`), без заливки.

## 4. Фоны и текстуры

### 4.1. Фон итогового экрана — P2

- **Путь:** `public/media/menu/office-night.webp`
- **Формат:** webp, 1600×900, до 350 КБ
- **Сюжет:** тот же кабинет или здание, но вечером/ночью — визуальная точка в
  конце партии. Центр кадра перекрывается кольцом индекса и статистикой,
  поэтому главное должно читаться по краям.

### 4.2. Дополнительные бумаги — P3

- **Путь:** `public/media/textures/paper-aged.webp`, `paper-grid.webp`
- Разные документы (договор, накладная, записка) могли бы иметь разную бумагу:
  состаренную, в клетку, с типографской сеткой. Требования те же, что к
  основной текстуре: светлая, бесшовная, малоконтрастная, до 300 КБ.

### 4.3. Декор документа — P3

- **Путь:** `public/media/ui/clip.png`, `staple.png`, `coffee-ring.png`
- PNG с альфой, до 40 КБ, высота 120–220 пикселей. Скрепка, степлерная скоба,
  след от кофейной кружки в углу документа — мелочи, которые делают бумагу
  живой. Накладываются поверх карточки с небольшим случайным поворотом.

## 5. Требования, общие для всех изображений

1. **Никакого текста на ассетах** (кроме логотипа и печатей) — игра
   локализована на русский, но текст должен оставаться в коде.
2. **Тёмные края.** Все полноэкранные фоны перекрываются градиентом снизу и
   сверху: светлые детали по краям уйдут в темноту, это нормально.
3. **Безопасная зона.** В фонах центральные 60% по ширине и 50% по высоте
   закрыты интерфейсом.
4. **Без рамок и виньеток** внутри изображения — их добавляет код, две виньетки
   дают грязь.
5. **Цветовой профиль sRGB**, 8 бит. Изображения в P3/Adobe RGB станут блёклыми.
6. **Имена файлов** — латиницей, строчными, через дефис.

## 7. Как проверить, что ассет подхватился

1. `npm run dev`, открыть игру.
2. Консоль браузера (F12) → вкладка Network → фильтр по имени файла:
   ответ должен быть `200` и правильный `Content-Type`.
3. Визуально: логотип заменяет флаг, печати — рамки на экране разбора,
   рамки панелей — скругления карточек.
4. Если файл не подхватился, почти всегда причина одна: путь или расширение
   отличаются от указанных выше.
