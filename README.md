# КРАСНЫЙ ФЛАГ

Короткая браузерная мини-игра о противодействии коррупции.
Игрок — сотрудник, который проверяет документы, письма и переписки и должен
заметить в них признаки коррупционного риска.

> «Заметь то, что другие могут не заметить.»

Одна партия — 10 документов и 90 секунд, примерно 2–4 минуты с учётом разборов.

## Запуск

```bash
npm install
npm run dev       # разработка, http://localhost:5173
npm run build     # проверка типов + production-сборка в dist/
npm run preview   # просмотр собранной версии
npm test          # тесты подсчёта очков и целостности контента
```

Сервер и база данных не нужны: всё работает в браузере, контент лежит в
`src/data/scenarios.ts`.

## Как играть

1. В документе кликайте по фрагментам, которые кажутся признаком риска:
   верный клик — **+100**, ошибочный — **−100**.
2. Затем примите решение: **ПРОПУСТИТЬ** или **ОСТАНОВИТЬ**
   (+200 за верное, −200 за ошибочное, +100 сверху за безупречный раунд).
3. После каждого документа — короткий разбор: что найдено, что пропущено и почему.
   На время разбора таймер останавливается.
4. В финале показывается **ИНДЕКС ЧИСТОТЫ** (0–100%):

   `55% × доля найденных признаков + 45% × доля верных решений − 5% за каждое ложное срабатывание`

Сложность растёт: первые документы очевидны, последние содержат серые зоны —
например, просьбу не выносить в отчёт персональные данные (это законно) рядом с
просьбой скрыть эпизод с переплатой (это нарушение). Десятый документ не содержит
нарушений вовсе — чтобы клик «на всякий случай» имел цену.

## Архитектура

```
src/
  core/        состояние и логика, не знает о DOM
    types.ts     контракты данных
    rules.ts     подсчёт очков, индекс чистоты, звания (покрыто тестами)
    engine.ts    игровой движок: фазы, таймер, подписки
    audio.ts     звуковые эффекты на Web Audio API, без файлов
  data/
    scenarios.ts 10 игровых ситуаций
  ui/          слой представления
    app.ts       контроллер: связывает движок с экранами
    documentView.ts  рендер документа из данных
    dom.ts       помощники и форматирование
    screens/     стартовый экран, игра, разбор раунда, финал, «О проекте»
  styles/      токены, база, HUD, документ, экраны, анимации
```

UI перерисовывается только при смене фазы; значения HUD обновляются точечно
на каждом кадре таймера.

### Как добавить новую ситуацию

Дописать объект в массив `scenarios` — движок и UI менять не нужно:

```ts
{
  id: 's11-example',
  title: 'Заголовок',
  kind: 'email',                 // email | chat | contract | memo | invoice | form
  source: 'Подпись под заголовком',
  brief: 'Задача игроку',
  blocks: [
    { type: 'lines', lines: [{ text: 'Обычный текст и {{s11-flag}} внутри него.' }] },
  ],
  hotspots: [
    { id: 's11-flag', text: 'подозрительный фрагмент', suspicious: true, note: 'Почему это риск.' },
  ],
  correctDecision: 'stop',       // stop | pass
  explanation: 'Разбор после раунда.',
}
```

Маркер `{{id}}` в тексте превращается в кликабельный элемент. Тесты в
`src/core/rules.test.ts` проверяют, что все маркеры и элементы согласованы.

## Технологии

Vite, TypeScript, HTML/CSS. Без React и других фреймворков, без внешних
изображений и шрифтов: иконки и документы нарисованы средствами CSS и SVG,
звук синтезируется через Web Audio API.
