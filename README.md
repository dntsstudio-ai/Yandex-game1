# КРАСНЫЙ ФЛАГ

Короткая браузерная мини-игра о противодействии коррупции.
Игрок — сотрудник, который проверяет документы, письма и переписки и должен
заметить в них признаки коррупционного риска.

> «Заметь то, что другие могут не заметить.»

Одна партия — 10 документов, у каждого свой таймер. Проверка занимает
примерно 3–5 минут вместе с разборами.

## Запуск

```bash
npm install
npm run dev       # разработка, http://localhost:5173
npm run build     # проверка типов + production-сборка в dist/
npm run preview   # просмотр собранной версии
npm test          # тесты подсчёта очков и целостности контента
```

Сервер и база данных не нужны: всё работает в браузере, контент лежит в
`src/data/scenarios.ts`.

## Как играть

1. В документе кликайте по фрагментам, которые кажутся признаком риска:
   верный клик — **+100**, ошибочный — **−100**.
2. Затем примите решение: **ПРОПУСТИТЬ** или **ОСТАНОВИТЬ**
   (+200 за верное, −200 за ошибочное, +100 сверху за безупречный раунд).
3. После каждого документа — короткий разбор: что найдено, что пропущено и почему.
   Таймер следующего документа начинается заново, так что время на разбор не тратится.
   Если время документа истекло, решение считается непринятым: найденное засчитывается,
   но начисляется штраф как за ошибку.
4. В финале показывается **ИНДЕКС ЧИСТОТЫ** (0–100%):

   `55% × доля найденных признаков + 45% × доля верных решений − 5% за каждое ложное срабатывание`

Сложность растёт: первые документы очевидны, последние содержат серые зоны —
например, просьбу не выносить в отчёт персональные данные (это законно) рядом с
просьбой скрыть эпизод с переплатой (это нарушение). Десятый документ не содержит
нарушений вовсе — чтобы клик «на всякий случай» имел цену.

## Время на документ

Таймер сбрасывается на каждом документе, а лимит растёт вместе со сложностью:

| Документы | Время |
|---|---|
| 1–2 (очевидные) | 30 с |
| 3–5 | 35 с |
| 6–7 | 40 с |
| 8–10 (серые зоны) | 45 с |

Значение задаётся полем `timeLimitMs` в ситуации; без него берётся
`ROUND_DURATION_MS` из `src/core/rules.ts`.

## Звук

- **Фоновая музыка** — файл `public/media/music/theme.mp3` (89 с, зацикленно).
  Без файла синтезируется спокойная минорная тема из четырёх аккордов
  с арпеджио.
- **Эффекты** — клики, шелест бумаги, штамп решения, тиканье последних секунд,
  итоговый аккорд. Для звука есть файл `public/media/sfx/<имя>.mp3` — играет
  он, нет — синтезируется замена. Сейчас файлами закрыты все эффекты, кроме
  тика счётчика на итоговом экране.
- Записанные эффекты игра приводит к одному виду: выравнивает громкость,
  гасит последние 12 мс, отрезает тишину в начале и берёт только первое
  событие, если дальше идёт пауза длиннее 0,1 с. Последнее — не прихоть:
  часть присланных файлов оказалась дорожками (в `click` три щелчка подряд,
  в `tick` — тридцать четыре тика), а игра проигрывает такой звук на каждое
  нажатие и каждую секунду таймера.
- Музыка, эффекты и громкость переключаются в разделе **НАСТРОЙКИ** и
  сохраняются в браузере.

## Обучение

После «НАЧАТЬ ПРОВЕРКУ» игра предлагает пройти короткое обучение —
меньше минуты, четыре слайда: найти признак риска, не нажимать всё
подряд, принять решение, следить за временем. На слайдах с действием
кнопка «ДАЛЬШЕ» появляется только после него. «ПРОПУСТИТЬ ОБУЧЕНИЕ»
доступно всегда.

Обучение живёт между меню и первым документом и движка не касается: у
него свой учебный документ, свои клики и свой таймер, основной счёт
оно не трогает.

**Гид — ИНСПЕКТОР №04.** Функциональный помощник, а не персонаж
новеллы. Поза — это имя файла в `public/media/guide`: добавить новую
можно, положив картинку рядом и дописав строку в список поз. Пока
картинка не загрузилась, показывается нарисованный средствами CSS
силуэт, поэтому пустой рамки не бывает.

## Во время проверки

**Серия.** Растёт на верных отметках, рвётся ошибочной отметкой и
неверным итоговым решением. С двух подряд в HUD появляется индикатор,
на трёх и пяти даются бонусы. Бонус начисляется один раз на пороге,
а не на каждой следующей отметке.

**Подсказка** стоит 50 очков и доступна один раз на документ. Подсветка
ложится на строку, а не на сам фрагмент: подсказка указывает направление
поиска и не делает клик за игрока.

**Увеличение** масштабирует карточку целиком через `transform`, поэтому
кликабельные области растут вместе с текстом. Таймер и кнопки решений
остаются над затемнением. Возврат — повторным нажатием, кликом по фону
или Esc.

**Папка дела** показывает номер, постоянный для документа, и состояние:
«НА ПРОВЕРКЕ» или «КРАСНЫХ ФЛАГОВ: N».

## Главное меню

Меню — «прямая трансляция с камеры наблюдения» у здания ОАО «Чистые Руки».

**Появление.** Из темноты проявляется город, в здании загорается свет, затем
по очереди выходят флаг, «КРАСНЫЙ», «ФЛАГ», подзаголовок, кнопки и рамка
камеры — около 4,6 секунды. Любой клик или клавиша пропускают интро.

**Жизнь кадра.** Дрейф камеры (масштаб 1.005 → 1.02 за 34 секунды), параллакс
за курсором, колышущийся флаг, пыль и листья на canvas, дыхание света в окнах,
зерно плёнки, луч по фасаду, редкая машина в глубине и бегущая строка лозунгов.

**Вход в игру.** По кнопке «НАЧАТЬ ПРОВЕРКУ» камера с ускорением наезжает на
вход, свет в дверях разгорается, интерфейс гаснет, экран уходит в чёрный —
и партия начинается «внутри здания».

Вся режиссура — на классах экрана: `menu-intro` → `menu-live` → `menu-skip`
(пропуск) → `menu-exit` (вход). Анимируются только `transform` и `opacity`.

Сцена останавливается при уходе с экрана, при скрытой вкладке и при системной
настройке «уменьшить движение». Если в первые секунды частота кадров ниже 34,
сцена сама переходит в облегчённый режим: камера и свет остаются, декоративные
слои и цикл пыли выключаются.

## Итоговый экран

Финал оформлен как **протокол проверки**: бланк с номером и датой, кольцо
индекса чистоты, звание и путь до следующего, разбор индекса на составляющие,
лента из десяти документов с отметками, сводка и печать «ПРОВЕРЕНО» при
индексе от 65 %.

**Разбор индекса.** Три шкалы показывают, из чего он сложился: найденные
признаки (до 55 очков), верные решения (до 45) и штраф за ложные срабатывания
(не больше половины набранного). Числа берутся из `purityBreakdown()` —
той же функции, что считает сам индекс, поэтому расхождений быть не может.

**Лента документов.** Десять клеток со значком состояния: `✓` безупречно,
`!` решение верное, но часть признаков пропущена, `✕` неверное решение,
`◷` время вышло. Под лентой — легенда: цвет нигде не остаётся единственным
признаком, у каждого состояния есть значок и подпись, а наведение показывает
название документа.

**Рекорд.** Лучший индекс хранится в браузере (`src/core/records.ts`). Первая
партия рекордом не считается — сравнивать ещё не с чем.

**Разбор ошибок.** Кнопка «ПОКАЗАТЬ, ГДЕ Я ОШИБСЯ» открывает список
документов, где были пропуски или лишние отметки, с теми же пояснениями,
что игрок видел бы в игре. Документы без ошибок в список не попадают.

**Появление.** Протокол собирается по тактам: шапка, кольцо со счётчиком,
полоса до следующего звания, печать, шкалы, отметки документов, сводка и
кнопки — около 3,4 секунды. Любой клик или клавиша показывают всё сразу, при
системной настройке «уменьшить движение» анимации не запускаются вовсе.

Колонки протокола включаются по ширине самой карточки (`@container`), а не
окна: в режиме подгонки под телефон сцена всегда 1440 px, и медиазапрос по
окну оставлял бы одну колонку на широком поле.

## Бумага документов

Сорт бумаги выбирается по типу документа: письма и переписка печатаются на
обычной, накладные и анкеты — на клетчатой, договоры и служебные записки —
на состаренной. Сверху ложатся украшения: скрепка в правом верхнем углу,
скоба степлера в левом, след от кофейной кружки за нижним краем. Набор
украшений и угол наклона считаются из идентификатора ситуации — документ
выглядит одинаково при каждом заходе, но по-разному у разных документов.

Без файлов текстур и украшений всё работает на встроенных CSS-заменах.

## Экран телефона

На телефоне в альбомной ориентации игра не перестраивает вёрстку, а показывает
ту же сцену, что и на компьютере, целиком уменьшенной: сцена 1440×780 масштабируется
под экран одним `transform`. Все десять документов, все экраны разбора и итоговый
экран помещаются без прокрутки (проверено автотестом на 844×390).

В книжной ориентации появляется подсказка повернуть устройство с кнопкой
«Играть вертикально» — тогда работает обычная адаптивная вёрстка, а выбор
запоминается.

## Ассеты

Изображения лежат в `public/media` и подхватываются автоматически; без них
работают встроенные замены. Полное техническое задание на все ассеты —
[`docs/ASSETS.md`](docs/ASSETS.md), краткая таблица — в `public/media/README.md`.

| Файл | Заменяет |
|---|---|
| `menu/headquarters.webp` | фон главного меню |
| `textures/paper.webp` | CSS-текстуру бумаги документа |
| `textures/backdrop.webp` | градиентный фон сцены |
| `ui/logo.webp` | нарисованный флаг и текстовый заголовок в меню |
| `ui/stamp-*.webp` | нарисованные рамки печатей на экране разбора |
| `ui/panel-frame.webp` | скругления карточек — рамкой 9-slice |
| `ui/button-frame.webp` | заливку главной кнопки экрана |
| `menu/office-night.webp` | тёмный фон итогового экрана |
| `textures/paper-grid.webp` | бумагу бланков и накладных |
| `textures/paper-aged.webp` | бумагу договоров и служебных записок |
| `ui/clip.webp`, `staple.webp`, `coffee-ring.webp` | украшения бумаги |
| `ui/icons.svg` | иконки HUD, настроек и сводки протокола |
| `ui/risk-marker.webp` | значок найденного признака риска |
| `ui/streak-badge.webp` | значок серии в HUD |
| `ui/hint.webp`, `zoom.webp` | значки на кнопках инструментов |
| `ui/case-tab.webp` | табличку с номером дела |
| `guide/<поза>.webp` | нарисованный силуэт гида |
| `music/theme.mp3` | синтезированную музыку |
| `sfx/<имя>.mp3` | синтезированный звуковой эффект |

Расширение подбирается автоматически (`.webp`, `.png`, `.svg`, `.jpg`), поэтому
файл достаточно положить по нужному пути в любом из этих форматов.

Спрайт иконок — исключение: он загружается один раз и вставляется прямо в
документ. `<use href="файл.svg#id">` на внешний файл браузеры не
поддерживают, ссылки работают только внутри одного документа. Без файла
иконки просто не показываются, подписи остаются текстовыми.

## Архитектура

```
src/
  core/        состояние и логика, не знает о DOM
    types.ts     контракты данных
    rules.ts     подсчёт очков, индекс чистоты, звания (покрыто тестами)
    records.ts   лучший результат игрока в localStorage (покрыто тестами)
    engine.ts    игровой движок: фазы, таймер документа, подписки
    settings.ts  настройки игрока с сохранением в localStorage
    assets.ts    необязательные внешние файлы и пути к ним
    sound/
      context.ts общий аудиоконтекст, шина громкости, реверберация
      sfx.ts     звуковые эффекты: файл или синтез
      samples.ts загрузка записанных эффектов
      music.ts   фоновая музыка: файл или синтезированная тема
  data/
    scenarios.ts 10 игровых ситуаций
  ui/          слой представления
    app.ts       контроллер: связывает движок с экранами
    documentView.ts  рендер документа из данных
    dom.ts       помощники и форматирование
    icons.ts     спрайт иконок: загрузка и разметка (покрыто тестами)
    guide.ts     гид: позы и реплики
    menuScene.ts живой фон меню: камера, пыль, свет, рамка наблюдения
    dust.ts      холст с пылью: один canvas для меню и итогового экрана
    screens/     старт, обучение, игра, разбор раунда, финал,
                 разбор ошибок, «О проекте», настройки
  styles/      токены, база, HUD, документ, экраны, анимации
```

UI перерисовывается только при смене фазы. Значения HUD пишутся в DOM лишь
при реальном изменении: раньше текст и проценты пересчитывались шестьдесят раз
в секунду, и игровой экран выдавал 31 кадр вместо 54 на программном рендеринге.

По той же причине у карточки протокола нет `backdrop-filter`: внутри неё живёт
холст с пылью, и размытие подложки пересчитывалось бы на каждом кадре —
16 кадров в секунду вместо 50.

И по ней же у украшений бумаги нет собственной анимации появления. В её
кадрах стоял поворот через переменную `--decor-tilt`, из-за чего браузер не
мог отдать анимацию композитору: даже завершённая, она перерисовывала
карточку документа каждый кадр, и большой полупрозрачный след от кружки
ронял игровой экран до 25 кадров в секунду. Без неё — 60.

### Как добавить новую ситуацию

Дописать объект в массив `scenarios` — движок и UI менять не нужно:

```ts
{
  id: 's11-example',
  title: 'Заголовок',
  kind: 'email',                 // email | chat | contract | memo | invoice | form
  source: 'Подпись под заголовком',
  brief: 'Задача игроку',
  blocks: [
    { type: 'lines', lines: [{ text: 'Обычный текст и {{s11-flag}} внутри него.' }] },
  ],
  hotspots: [
    { id: 's11-flag', text: 'подозрительный фрагмент', suspicious: true, note: 'Почему это риск.' },
  ],
  correctDecision: 'stop',       // stop | pass
  timeLimitMs: 35_000,           // необязательно: своё время на документ
  explanation: 'Разбор после раунда.',
}
```

Маркер `{{id}}` в тексте превращается в кликабельный элемент. Тесты в
`src/core/rules.test.ts` проверяют, что все маркеры и элементы согласованы.

## Технологии

Vite, TypeScript, HTML/CSS. Без React и других фреймворков, без внешних
изображений и шрифтов: иконки и документы нарисованы средствами CSS и SVG,
звук и музыка синтезируются через Web Audio API. Единственная внешняя
загрузка — шрифты Inter и Lora с Google Fonts; если они недоступны,
подставляются системные.
