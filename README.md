# КРАСНЫЙ ФЛАГ

Короткая браузерная мини-игра о противодействии коррупции.
Игрок — сотрудник, который проверяет документы, письма и переписки и должен
заметить в них признаки коррупционного риска.

> «Заметь то, что другие могут не заметить.»

Одна партия — 10 документов, у каждого свой таймер. Проверка занимает
примерно 3–5 минут вместе с разборами.

## Запуск

```bash
npm install
npm run dev       # разработка, http://localhost:5173
npm run build     # проверка типов + production-сборка в dist/
npm run preview   # просмотр собранной версии
npm test          # тесты подсчёта очков и целостности контента
```

Сервер и база данных не нужны: всё работает в браузере, контент лежит в
`src/data/scenarios.ts`.

## Как играть

1. В документе кликайте по фрагментам, которые кажутся признаком риска:
   верный клик — **+100**, ошибочный — **−100**.
2. Затем примите решение: **ПРОПУСТИТЬ** или **ОСТАНОВИТЬ**
   (+200 за верное, −200 за ошибочное, +100 сверху за безупречный раунд).
3. После каждого документа — короткий разбор: что найдено, что пропущено и почему.
   Таймер следующего документа начинается заново, так что время на разбор не тратится.
   Если время документа истекло, решение считается непринятым: найденное засчитывается,
   но начисляется штраф как за ошибку.
4. В финале показывается **ИНДЕКС ЧИСТОТЫ** (0–100%):

   `55% × доля найденных признаков + 45% × доля верных решений − 5% за каждое ложное срабатывание`

Сложность растёт: первые документы очевидны, последние содержат серые зоны —
например, просьбу не выносить в отчёт персональные данные (это законно) рядом с
просьбой скрыть эпизод с переплатой (это нарушение). Десятый документ не содержит
нарушений вовсе — чтобы клик «на всякий случай» имел цену.

## Время на документ

Таймер сбрасывается на каждом документе, а лимит растёт вместе со сложностью:

| Документы | Время |
|---|---|
| 1–2 (очевидные) | 30 с |
| 3–5 | 35 с |
| 6–7 | 40 с |
| 8–10 (серые зоны) | 45 с |

Значение задаётся полем `timeLimitMs` в ситуации; без него берётся
`ROUND_DURATION_MS` из `src/core/rules.ts`.

## Звук

- **Фоновая музыка** — спокойная минорная тема из четырёх аккордов с арпеджио,
  синтезируется на Web Audio API. Если в проект добавлен файл
  `public/media/music/theme.mp3`, играет он.
- **Эффекты** — клики, шелест бумаги, штамп решения, тиканье последних секунд,
  итоговый аккорд. Тоже синтезируются, внешних файлов нет.
- Музыка, эффекты и громкость переключаются в разделе **НАСТРОЙКИ** и
  сохраняются в браузере.

## Главное меню

Меню — «прямая трансляция с камеры наблюдения» у здания ОАО «Чистые Руки»:

- медленное движение камеры по фотографии и параллакс за курсором;
- пыль в воздухе на canvas, световой луч по фасаду, сканлайны и редкий сбой сигнала;
- рамка камеры с часами и бегущая строка корпоративных лозунгов.

Анимация останавливается при уходе с экрана, при скрытой вкладке и при
системной настройке «уменьшить движение». Дорогие эффекты (CSS-фильтры,
blend-режимы поверх движущихся слоёв) намеренно не используются: с ними
частота кадров падала с 51 до 10 в секунду на программном рендеринге.

## Ассеты

Изображения лежат в `public/media` и подхватываются автоматически; без них
работают встроенные замены. Подробности и требования — в `public/media/README.md`.

| Файл | Заменяет |
|---|---|
| `menu/headquarters.webp` | фон главного меню |
| `textures/paper.webp` | CSS-текстуру бумаги документа |
| `textures/backdrop.webp` | градиентный фон сцены |
| `music/theme.mp3` | синтезированную музыку |

## Архитектура

```
src/
  core/        состояние и логика, не знает о DOM
    types.ts     контракты данных
    rules.ts     подсчёт очков, индекс чистоты, звания (покрыто тестами)
    engine.ts    игровой движок: фазы, таймер документа, подписки
    settings.ts  настройки игрока с сохранением в localStorage
    assets.ts    необязательные внешние файлы и пути к ним
    sound/
      context.ts общий аудиоконтекст, шина громкости, реверберация
      sfx.ts     звуковые эффекты
      music.ts   фоновая музыка: файл или синтезированная тема
  data/
    scenarios.ts 10 игровых ситуаций
  ui/          слой представления
    app.ts       контроллер: связывает движок с экранами
    documentView.ts  рендер документа из данных
    dom.ts       помощники и форматирование
    menuScene.ts живой фон меню: камера, пыль, свет, рамка наблюдения
    screens/     старт, игра, разбор раунда, финал, «О проекте», настройки
  styles/      токены, база, HUD, документ, экраны, анимации
```

UI перерисовывается только при смене фазы; значения HUD обновляются точечно
на каждом кадре таймера.

### Как добавить новую ситуацию

Дописать объект в массив `scenarios` — движок и UI менять не нужно:

```ts
{
  id: 's11-example',
  title: 'Заголовок',
  kind: 'email',                 // email | chat | contract | memo | invoice | form
  source: 'Подпись под заголовком',
  brief: 'Задача игроку',
  blocks: [
    { type: 'lines', lines: [{ text: 'Обычный текст и {{s11-flag}} внутри него.' }] },
  ],
  hotspots: [
    { id: 's11-flag', text: 'подозрительный фрагмент', suspicious: true, note: 'Почему это риск.' },
  ],
  correctDecision: 'stop',       // stop | pass
  timeLimitMs: 35_000,           // необязательно: своё время на документ
  explanation: 'Разбор после раунда.',
}
```

Маркер `{{id}}` в тексте превращается в кликабельный элемент. Тесты в
`src/core/rules.test.ts` проверяют, что все маркеры и элементы согласованы.

## Технологии

Vite, TypeScript, HTML/CSS. Без React и других фреймворков, без внешних
изображений и шрифтов: иконки и документы нарисованы средствами CSS и SVG,
звук и музыка синтезируются через Web Audio API. Единственная внешняя
загрузка — шрифты Inter и Lora с Google Fonts; если они недоступны,
подставляются системные.
